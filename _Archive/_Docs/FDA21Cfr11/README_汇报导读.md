# 21 CFR Part 11 资料汇总与汇报导读

> 给领导的 3 分钟版：这个文件夹回答一个问题——**我们卖给受 FDA 监管客户的设备/软件，怎么满足 FDA 电子记录与电子签名法规（21 CFR Part 11），以及对外应该怎么说。**

## 一句话结论

**FDA 不颁发 Part 11 证书。** 合规 = 设备具备 Part 11 技术能力（Part 11 capable）+ 客户现场验证（IQ/OQ/PQ）+ SOP 与变更控制。对外口径只能说 "Part 11 capable 并提供验证支持包"，**不得说"FDA Part 11 认证通过"**。

## 三个汇报要点

1. **没有官方认证这回事。** Part 11 不是 CE/UL 式的产品认证，市场上任何 "Part 11 Certified" 都是供应商或咨询公司的自我声明。FDA 检查时看的是系统本身、审计追踪和 SOP。（依据：`21 CFR Part 11 客户设备合规说明.md` 第 1、4、5 节）
2. **B&R mapp 平台已有官方背书，但有边界。** B&R 官方符合性声明只覆盖 MpAudit 和 MpUser/MpUserX（V5.0.0+）；mapp Database、Data、Report 等组件无任何声明，责任在我们自己。（依据：`00_原文/BR_mapp_Services_Declaration_of_conformity.pdf`；覆盖关系见 `mapp_Services组件_Part11声明覆盖范围矩阵.html`）
3. **SD_SMA_Runtime 的合规路径已定：继承 mapp 体系，不自建。** 方向成立，但现状有 4 个断点（网络旁路、操作无归属、审计断链、自有记录不受控），需完成 R1–R7 升级，其中 R1 网络封闭 / R2 身份传递 / R3 审计上交为 P0。（依据：`SD_SMA_Runtime Part 11 升级说明.md` 第 4、5、7 节）

## 引用注意事项

- 自产 3 份文件（2 份 md + 1 份 html）可直接用于内部汇报和客户沟通；`00_原文/` 仅供条款溯源，客户要原文时给 B&R 声明和法规链接即可。
- 所有对外材料统一口径：**"Part 11 capable"**，禁止出现 "认证""证书" 字样。
- 升级说明.md 中的 P0 三项完成前，**不要对客户承诺 Runtime 已合规**；P0 完成后可按其第 6 节口径对齐验证计划。
- 引用法规条款时用 "§11.10(d)" 格式，并与中文翻译件核对，避免只引二手转述。
