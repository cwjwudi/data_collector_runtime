核心结论

FDA 不颁发 Part 11 证书。合规 = 设备具备 Part 11 技术能力（Part 11 capable）＋ 客户现场验证（IQ/OQ/PQ）＋ SOP 与变更控制。

对外统一口径：只说 "Part 11 capable 并提供验证支持包"，禁止出现 "FDA Part 11 认证通过" 字样。
要点 ①

没有官方认证这回事

Part 11 不是 CE/UL 式产品认证。市场上任何 "Part 11 Certified" 均为供应商或咨询公司的自我声明，FDA 不承认、不授权任何第三方发证。检查时看的是系统本身、审计追踪和 SOP。

→ 详见《客户设备合规说明》第 1、4、5 节
要点 ②

B&R 平台有背书，但有边界

B&R 官方符合性声明只逐条评估了 MpAudit 和 MpUser/MpUserX（V5.0.0+）；mapp Database、Data、Report 等组件无任何声明，合规责任在我们自己。

→ 详见 B&R 声明原文 + 覆盖范围矩阵图
要点 ③

Runtime 走"继承"路线

SD_SMA_Runtime 不自建合规功能，而是继承 mapp Services 体系。架构方向成立，但现状有 4 个断点，须完成 R1–R7 升级；P0 三项完成前不对客户承诺合规。

→ 详见《Runtime 升级说明》第 4、5、7 节

SD_SMA_Runtime Part 11 升级说明.md

项目升级方案 · R1–R7▶

回答"Runtime 如何继承 mapp Services 已有的合规能力"。客户架构：Hypervisor 同一工控机上 AR 侧跑 mapp Services，Windows 侧 mappView 全屏锁定为唯一入口，Runtime 网页经 WebViewer 分权呈现。

  • 继承了什么：账号权限、密码策略、审计追踪、电子签名全部由 mapp UserX/AuditTrail 承担，Runtime 不重复自建
  • 四个断点：A 网络旁路（8090–8094 端口可直连）／B 操作无归属（Runtime 不知道是哪个用户）／C 审计断链（Runtime 操作不入 mapp 审计）／D 自有记录不受控（数据、报表、时钟）
  • 升级项：R1 网络封闭、R2 身份传递、R3 审计上交（P0）；R4 页面分级、R5 记录完整性、R6 时间同步、R7 Kiosk 加固（P1）
  • 第 6 节：升级完成后对客户/审计方的标准声明口径（可直接引用）

三、Runtime 升级路线图（项目决策点）

P0 是合规声明的地基；P0 完成前不对客户承诺 Runtime 合规

P0 · 必须先做（3 项）

  • R1 网络封闭：服务只绑内部网卡＋防火墙白名单 → 外部访问 8090–8094 全部失败
  • R2 身份传递：mappView 登录态经 token 传到 Runtime → 无 token 的写请求被拒
  • R3 审计上交：Runtime 写操作经 OPC UA 记入 mapp AuditTrail → 审计页可查

P1 · 随后补齐（4 项）

  • R4 页面分级：操作页仅高权限角色可见可开
  • R5 记录完整性：数据库 append-only 账号 ＋ 报表 SHA-256 哈希入审计
  • R6 时间同步：AR 与 Windows 同源对时，审计时间轴一致
  • R7 Kiosk 加固：Windows Assigned Access，禁逃逸（客户 IT 协同）

四、引用注意事项

✅ 可以：自产 4 份文件直接用于内部汇报与客户沟通；引用 B&R 声明作为平台背书；按 "§11.10(x)" 格式引用法规条款。
⛔ 禁止：任何对外材料出现 "Part 11 认证 / 证书" 字样；P0 三项（R1–R3）完成前对客户承诺 Runtime 已合规；将 00_原文/ 中的整份 PDF 直接转发客户（给链接和 B&R 声明即可）。
